# Bailian Three-Stage Generation Plan

Approved design: Beijing region, one server-side DASHSCOPE_API_KEY, explicit confirmation between text, image and video generation, default 8-second 720P portrait video. Keep template generation and publication gates.

Architecture: separate Bailian HTTP client and persistent AI job orchestration attached to Studio. No API keys in browser, job snapshots or logs. Qwen compatible chat; wanx asynchronous image synthesis; Wan 2.7 first_frame media protocol. Use current model identifiers exactly as configured, never silently substitute models.

- [x] Test provider payloads, safe downloads, configuration, job recovery and missing-key behavior first.
- [x] Implement config.py and bailian.py; .env loading with process environment priority and a blank key template.
- [x] Implement ai_studio.py: durable remote IDs, stages, progress/errors, authenticated images and final local media registration.
- [x] Wire Studio/HTTP and Chinese UI for editable text, image preview and explicit image-to-video confirmation.
- [x] Update contracts/docs, run offline fake-provider end-to-end tests and existing regressions, restart service.

No live model calls without a supplied key. Async task POST is never retried automatically. Known remote IDs can be resumed after restart using GET. Unknown submission blocks further paid work until operator explicitly acknowledges checking the provider console. Poll timeout/download failure retains remote ID and allows query-only resumption. Only active local jobs count towards worker queue capacity; unsettled provider work still locks its owning task. Result URLs and base64 images are not exposed as public capabilities. Downloads accept only HTTPS Alibaba result hosts, bounded size/time, no redirects. Website and production deployment constraints remain unchanged.

Official protocol references checked 2026-09-23: help.aliyun.com/zh/model-studio/qwen3-6-plus, text-to-image-api-reference, image-to-video-general-api-reference, deep-thinking.
