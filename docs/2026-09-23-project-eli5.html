自主，不等于随意。主管可以决定先补资料还是先问你；但没批脚本不能制作，没批成片不能正式交付，没确认发布不能代发。
展开：为什么不是固定流水线，也不是完全放任？

固定的是目标与依赖：先有可信依据，才能写有依据的脚本；批准脚本后制作；成片预览审批后交付。可变的是调度：资料充分就不强行联网，字幕有错就局部修字幕，不一定从资料重新来。

框架和业务工作流不能同时启动同一项制作。主管提出动作，业务系统核验条件并保存正式结果，避免重复渲染或重复扣费。

像传一份“带版本号的作业”

数据流不是看谁在聊天，而是看：这一站拿到什么，做出什么，下一站用哪个版本。

图示表达产物依赖，不要求主管每次死板地执行一串相同调用。只有没有未满足依赖的工作才可并行。

新视频不能借旧视频的“批准章”。你批准 v1，系统改成 v2 后必须让你重新看、重新批。AI 说“检查通过”也不是你的正式批准。
展开：用一条知识讲解视频举例，看懂“交接规则”
  1. 你说：“根据这份知识资料，让固定虚构人物用通俗语言讲清一个知识点，自然点头和做手势，不编造结论。”这是例子，不指定实际知识领域或时长。
  2. 资料 Agent 把能用的事实整理出来，给出原始出处，不把“看起来好像是”当作事实。
  3. 脚本 Agent 写出脚本 v1；主管组织审查并请你批准。媒体 Agent 必须拿已批准的具体版本制作，关联人物参考、声音设定和实际台词音频版本。
  4. 审查发现第 6 秒字幕与实际台词不同，报告具体时间和证据；主管检查额度，再安排局部修复。
  5. 你看修订成片并批准，系统保存人、时间、决定及关联版本，最后交付同一成片。

所有子 Agent 向主管交接；任务单说明目标、依据、限制和产物。结果先保存，再汇报引用。没做完就说没做完，不随意跨项目读取资料。

这段视频是谁、说了什么，用的是哪份声音？每段人物视频关联人物参考版本、声音设定、实际音频、批准脚本与镜头。台词改了不能只改字幕；声音改了，要重新检查口型、时序与时长。新成片仍需审批。
展开：建议增加“人物档案”，但不新增数据库

记录人物标识、参考素材、声音设定、适用账号或项目范围与版本。首次建立人物和之后复用分开处理，不是每个镜头重新挑一张脸。

这份记录属于现有项目与素材管理。已确认且可复用的人物要求按长期记忆规则保存；具体文件、版本和审批以业务记录为准，不能仅凭记忆摘要选人物。

待定：具体字段、人物预览是否需要独立审批、实际固定音色与绑定方式。固定人物不等于服装和背景永远不能变化，也不能跨账号越权使用。

展开：记忆与上下文究竟有什么区别？

记忆是资料柜；上下文是这次摆到桌上的资料。不能把整柜文件全倒给每一个 Agent。先检查权限和项目范围，再挑相关内容。

长期检索不是“找到了就照做”：Milvus 找相似内容，仍要回 PostgreSQL 查原文、确认状态、版本与有效性。强制品牌规则必须直接读取，不能指望相似搜索碰巧命中。

你说“以后都用白色字幕”，可以按明确范围长期记住并反馈。你说“只有这一条别写价格”，不能自动改成永远不写价格。AI 自己猜出的偏好，要先让你确认。

资料不会放久了就自动变成长期记忆。过期规则停止使用；删除还要处理原文、向量、缓存及备份保留策略。正式审批和额度是业务记录，不能只存在一段 AI 摘要里。

展开：为什么不继续拆成几十个 Skills？

06 / MCP 与执行规则

手册教怎么干，工具才真正干活

🌐

资料检索 MCP

共享：资料＋审查

像查资料工具：找外部来源、读原文、留出处。

🗂️

项目资料与素材 MCP

共享：五个角色按权限

像内部文件室：读需求、找脚本、查素材和版本。

🧪

媒体检测 MCP

共享：媒体＋审查

像检查台：测参数、抽画面、听声音、认文字。

🛠️

媒体制作 MCP

专属：只有媒体 Agent

像制作设备：复用固定人物，制作声音、人物说话与自然动作片段，再合成修复。

共 4 组创作 MCP：3 组共享＋1 组专属。共享不代表能看所有项目；专属不代表要单买一台服务器。工具与供应商的实际接入尚需实现。

展开：ASR、OCR 是什么？工具返回结果就算成功了吗？

ASR：把实际听到的语音转成文字。OCR：识别画面上的文字。配合参数探测与抽帧，给审查提供证据。

识别结果可能出错。抽查几张画面不代表全片每帧都检查过；工具也不能保证事实或素材授权正确。

媒体工具输入要有关联任务、镜头、脚本版本、参考素材、不可改变的事实与输出规格。输出要有操作编号、状态、实际产物引用、实际参数及可取得的用量费用。“已受理”不是“已生成”，“未知”不是“失败”或“零成本”。

展开：人物说话工具，还要明确哪些输入输出？

输入：人物参考及版本、声音设定、批准台词、任务与镜头、自然表达要求和输出规格；采用音频驱动路线时提供实际台词音频版本。

输出：人物视频片段、实际参数、操作状态、所用人物和脚本及音频版本、可取得的用量费用。只有配音或静态图不算完成人物视频。

待验证：具体模型、供应商、是否另需口型或动作处理，以及口型与人物检测工具。不能把普通抽帧或语音转写当成已经全面检查口型；无法判断时交人工。

想象全任务只有四张“自动返工券”，每个阶段最多用一张。先碰到哪个限制，就按哪个停。

展开：返工与重试，最容易混淆的细节
  • 阶段一轮，不是每镜头各一轮。集中处理一批已定位的问题，不能不断加问题让一轮永远不结束。
  • 三张图都不合格时，每个受影响镜头只出一个修正版，不再新出三张；有选中的候选则优先修改它。
  • 修改后仍不合格，转人工。你提意见后自动修改也占额度；换版本、换 Agent、断线恢复不清零。
  • 技术故障首次失败后，适合重试时额外最多 2 次，即同一操作最多 3 次尝试；不同执行层不能各套一次限额。
  • “片段生成了但人物或台词不对”是返工；“请求临时失败”才可能是技术重试；超时结果不明先查询，不能直接重复扣费。
  • 超限时带着现有产物、问题、尝试记录和用量交给你，不是让 AI 无限互相改稿。
声音修改怎么计数，仍待明确。建议人物说话片段归入视频片段阶段，改配音导致重做片段作为一次关联修复，但这不是已定稿的计数规则。人物首次建立的额度也待明确；遇到无法归类的修改，先转人工，不增加第六个返工阶段，也不自行增加预算。

视频批准了，也不会自动发到抖音

方式一：你手动发

下载视频和发布文案 → 自行上传 → 回填链接或作品编号 → 核实公开状态。

方式二：系统代发

选择授权账号 → 预览发布设置 → 单独确认发布 → 受控提交 → 核实公开状态。

三件事分开：批准视频 ≠ 允许代发；提交成功 ≠ 已公开；结果未知 ≠ 可以再发一次。

代发需要实际可用的官方接口能力与有效授权，目前不能假定已接通。发布模块归属和文案准备职责待定，不因此新增第六个 Agent 或第五组创作 MCP。

展开：用简单算术理解，但这些不是实测成绩

假设有 10 个有效创作任务，在约定条件下完成 9 个，就是 90%。正常人工审批允许，但人接手制作完成，不能算系统自动完成。

假设 10 个任务的第一次人工审核都有结论，8 个直接批准，就是 80%。内部已经改过几轮仍要披露；“首次人工通过”不等于“第一次生成就完美”。待审任务单列。

同样质量与复杂度，原来人工做 100 分钟，用系统后实际人工用 70 分钟，就是下降 30%。其中审核和异常处理都算人工，无人看管的机器等待不算人工工时。

成本看同批全部成本除以合格交付数；发布看应完成的计划发布中核实公开的比例，手动与代发分列去重。完播率不能用来替代创作完成率。

知识对，讲得明白

知识准确、条件完整；解释通俗、例子不误导。人物再好看，也不能把知识讲错。

说得对，嘴型协调

不漏说、错说、加话。嘴部动作与实际音频配合，字幕与内容对应。

仍是同一位讲解者

跨镜头和跨视频对照人物参考；声音符合设定，不突兀变声。具体固定音色尚未选定。

动作自然，声画配合

表情、点头和手势不抢戏；按需使用的配图、字幕与讲解含义对应。不考核拿物品或精准指向。

来源、使用范围、版本属于业务校验，不与画质混成一个分数。口型通过不代表知识正确，检查结论不代替人工批准。
